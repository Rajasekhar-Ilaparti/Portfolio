Approach

How IWork

The principles behind every board I build.

01

Curiosity

Every project starts with understanding how something actually behaves — a datasheet, a waveform, a failing sensor. I'd rather trace a signal than guess at it.

02

Precision

Hardware doesn't forgive sloppy logic. A missed debounce or an off-by-one timer shows quickly that exactness isn't optional when code controls something physical.

03

Persistence

Firmware bugs rarely explain themselves. Staying with a problem through MPLAB breakpoints and Proteus reruns until the state machine behaves is where the real learning happens.

04

Test in stages

Each project ships with small test sketches — sensor, buzzer, Wi-Fi, storage — run in order before the full firmware, so problems are caught one layer at a time.

“If the firmware is wrong, the gate doesn't open. There's no ambiguity in that feedback loop — and that's what I like about it.”
